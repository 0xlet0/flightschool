# 함께 배우는 진행자 안내

진행자도 Lean 초보자라고 가정합니다. 수업 전 해야 할 일은 `lake build`, `lake exe flightschool`을 실행하고 해당 회차 과제·해답을 한 번 열어 보는 것입니다. 긴 `action_preserves`의 모든 전술을 설명할 준비는 필요 없습니다. 모르는 부분은 “현재 목표를 같이 확인하자”고 말해도 됩니다.

## 운영

4회 × 120분, 개인 복습·최종 정리 120분으로 총 10시간입니다. 수업별 시간표는 lessons에 있습니다. 설치가 막히면 이미 빌드되는 동료 환경에서 짝 활동을 진행하고 설치 해결은 복습 시간에 합니다. 교육용 저장소의 빌드가 깨진 상태로 수업을 시작하지 마세요.

입력자와 설명자를 15분마다 바꿉니다. 설명자는 “이 이벤트 전후의 상태”를 말하고 입력자는 계산으로 확인합니다. 7분 막히면 힌트 하나를 열고, 15분이면 해답을 비교합니다. 각 회차 마지막 10~15분에는 모든 조가 `lake build`를 통과시키고 한 문장으로 배운 점을 공유합니다. 일부러 깨뜨린 코드는 반드시 복구합니다.

## 회차별 체크포인트

| 회차 | 물어볼 질문 | 기대 답·대응 |
|---|---|---|
| 1 | send 두 번이 전송 두 번인가? | waiting이면 두 번째 send 무시; 상태를 먼저 본다 |
| 2 | 바깥 none과 pending none은 같은 뜻인가? | 이벤트 거절과 미확인 패킷 없음은 다르다 |
| 2 | 잘못된 ACK가 타입 검사에 걸리는가? | 번호 비교 없는 코드도 타입은 맞을 수 있다 |
| 3 | ACK를 잃으면 수신 수를 되돌리는가? | 아니다; 재전송에 ACK만 다시 보낸다 |
| 3 | 왜 Safe만 아니라 QueueValid도 필요한가? | 다음 메시지가 정당하다는 근거가 필요하다 |
| 3 | 왜 generalizing s인가? | 다음 이벤트에서는 시작 상태가 달라진다 |
| 4 | 반환 Action을 다시 실행해야 하는가? | 아니다; interpreter가 이미 적용했다 |
| 4 | 불변식을 지키면 결국 완료되는가? | 아니다; 빈 규칙표나 반복 손실도 안전하다 |

## 막혔을 때

- `lake`를 못 찾음: 새 터미널을 열거나 `. "$HOME/.elan/env"`를 실행합니다.
- toolchain 다운로드 실패: 네트워크·프록시·디스크 여유를 확인합니다. 공동 학습은 한 환경에서 먼저 진행할 수 있지만 개인 설치 완료와 혼동하지 않습니다.
- import를 못 찾음: 저장소 루트에서 먼저 `lake build`, 이후 `lake env lean ...`을 사용합니다. 파일 하나만 별도 디렉터리로 옮기지 않습니다.
- VS Code와 CLI 결과가 다름: 루트 폴더와 `lean-toolchain` 확인 후 Lean 서버를 재시작합니다.
- 증명 목표가 많음: `cases` 뒤 각 경우를 하나씩 읽고 아직 남은 목표를 확인합니다.
- 귀납 가정이 맞지 않음: `generalizing s`와 재귀 실행의 상태를 확인합니다.
- 빌드는 되는데 연습이 끝났는지 모름: exercises/README의 완료 조건과 `#guard`를 확인합니다. 시작 파일도 컴파일되는 것이 의도입니다.

## 최종 과제 평가 — 10점

| 항목 | 점수 | 관찰 가능한 기준 |
|---|---:|---|
| AST와 의미론 | 2 | 규칙표가 실제 interpreter 입력이며 거절 정책 설명 |
| 실행 사례 | 2 | 여섯 trace, 중복의 중간값, 예상 상태 일치 |
| local·trace invariant | 3 | 전제와 범위 명시, 모든 prefix 정리, 증명 구멍 없음 |
| 도달 불가능성 | 1 | 일반 trace의 safety에서 모순을 도출 |
| 가정과 보장 설명 | 2 | safety/liveness와 네 검증 수단의 차이 설명 |

통과 기준은 7점 이상이며 실행 가능한 모델과 일반 trace 증명은 필수입니다. 과제를 채점할 때 한 줄짜리 기존 정리 재사용 자체를 감점하지 않습니다. 단, E8에서는 귀납 구조를 직접 써야 하고, 최종 발표에서 초기·단계·trace 보존의 연결을 말할 수 있어야 합니다.

8시간으로 줄여야 하면 긴 산술 분기 읽기와 선택 심화를 생략합니다. AST 작성, trace 실행, 귀납 증명, 가정 설명은 유지합니다. 12시간까지 가능하면 수신 번호 단조성이나 재정렬 확장 중 하나를 선택합니다.
