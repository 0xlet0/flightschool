# 첫 주 Lean 빠른 참고

| 표기 | 읽는 법 | 이 저장소 예 |
|---|---|---|
| `def f (x : T) : U := ...` | T를 받아 U를 계산 | step, run |
| `inductive` | 가능한 경우를 나열 | Event, Message |
| `structure` | 필드를 묶음 | State, Rule |
| `{ s with queue := q }` | 일부 필드를 바꾼 새 값 | execAction |
| `Option T` | none 또는 some 값 | 거절 또는 성공 |
| `List T`, `[]`, `e :: es` | 목록, 빈 목록, 머리와 나머지 | trace |
| `xs ++ ys` | 두 목록을 이어 붙임 | 큐 전송 |
| `A × B`, `(a, b)` | 두 값의 쌍 | 상태와 명령 목록 |
| `Bool`, `==`, `&&` | 계산용 조건 | guard |
| `Prop`, `=`, `∧`, `∀` | 명제, 등식, 그리고, 모든 | Inv |
| `h : P` | P의 증거인 h | 초기 불변식 |
| `h.1`, `h.2` | 논리곱 또는 쌍의 각 부분 | Safe의 부등식 |
| `#check`, `#eval`, `#guard` | 타입 확인, 계산, 계산 검사 | 수업 파일 |

| 전술 | 할 일 | 실패하면 확인할 것 |
|---|---|---|
| `rfl` | 계산하면 같은 두 식 증명 | 등식이 계산만으로 같나? |
| `simp [f, h]` | 정의 f와 사실 h로 단순화 | 필요한 정의를 펼쳤나? |
| `cases x` | x의 모든 생성자 경우 분리 | Bool/Option/목록 중 무엇인가? |
| `intro x` | 전칭 변수나 전제 도입 | 목표가 ∀ 또는 →인가? |
| `exact h` | 목표와 같은 타입의 증거 사용 | h의 타입을 #check/Infoview로 확인 |
| `constructor` | 논리곱 등 생성자의 하위 목표 생성 | 지금 목표가 A ∧ B인가? |
| `apply lemma` | 정리의 결론에 맞추고 전제를 새 목표로 | 인자 순서·초기 상태가 맞나? |
| `induction es generalizing s` | 목록 귀납, 바뀔 상태 일반화 | 재귀 호출에서 s가 변하나? |

제공 보조 증명에 나오는 추가 도구: `rcases`는 가정의 묶음·경우를 분리합니다. `by_cases h : P`는 P와 그 부정 두 경우를 만듭니다. `rw [h]`는 등식으로 식을 바꿉니다. `simpa [...] using h`는 h와 목표를 단순화해 맞춥니다. `omega`는 자연수의 선형 산술 목표를 풉니다. 첫 주 필수 작성 과제는 위 표의 전술 중심입니다.

Infoview에서 `⊢` 위는 사용할 수 있는 변수와 가정, 아래는 지금 증명할 목표입니다. 오류가 나면 마지막 줄을 반복해 바꾸기보다 목표가 어떻게 바뀌었는지 읽으세요. Bool의 `true`와 명제의 증명은 같은 것이 아닙니다.
